# 2026-09-29 工作日志

## 修复（第三轮·最终）：延迟监控任务选择卡整块变绿

承接 2026-09-28 的两轮错误修复，本轮找到真正根因。

**用户新线索**：截图显示任务选择卡是**整块实色绿底 + 白色文字**（不是半透明柔光叠层），并明确要求「把光效颜色改回主色吧，检查别的原因并修复」。

**真正根因**：与光效无关。
- Naive UI `NSpin` 的主题变量 `color` / `textColor` 都等于 `primaryColor`
  （`node_modules/naive-ui/es/spin/styles/light.mjs`），`Spin.mjs` 把它们写成
  内联 CSS 变量 `--n-color` / `--n-text-color` 挂在 spin 根节点上，**沿 DOM 子树继承**。
- `PingChart.vue` 的任务选择卡片是唯一位于 `NSpin` 内部的玻璃元素：
  `class="... glass-surface-enabled"`，而 `.glass-surface-enabled` 的背景是
  `color-mix(in srgb, var(--n-color) 68%, transparent)` —— 于是背景被染成 68% 主色（绿）；
  卡片 `color: var(--n-text-color)` 同理被染成主色（浅色主色近白）。
- 光效 `::after` 只是 18% 透明度的柔光，不可能造成「整块实色绿底」。

**最终修复**：
1. `src/components/PingChart.vue`
   - 根节点 `:style` 增加 `'--ping-text': themeVars.textColorBase`。
   - 新增 scoped 规则（`:deep` 命中 `Spin.mjs` 生成的 `.n-spin-content` 插槽包裹层）：
     `.ping-chart :deep(.n-spin-content) { --n-color: var(--ping-surface); --n-text-color: var(--ping-text) }`
2. `src/styles/main.scss`：按用户要求**回滚光效为原主色版本**
   （`z-index: 1` + `color-mix(in srgb, var(--primary-color,#18a058) 18%, transparent)`），
   并删除此前为错误假设加的 `isolation`/`>:where(*)`/`html.dark` 中性色/`:has(.ping-chart)` 兜底。
3. `komari-theme.json`：`cardMouseGlow` 的 help 恢复为「颜色跟随主题主色」。

**验证**：`CODEBUDDY_SAFE_DELETE_ENABLED=0 pnpm build` 通过；编译产物确认
- `.ping-chart[data-v-37946562] .n-spin-content{--n-color:var(--ping-surface);--n-text-color:var(--ping-text)}`
- glow 规则回到 `z-index:1` + `#18a058` 主色
产物：`komari-theme-naive-build-unknown.zip`

**教训（重要）**：
1. 「某处发绿」不要先怀疑最近加的视觉效果，应先查 **Naive UI 组件自身注入的 `--n-*` 主题变量继承**：
   `NSpin`/`NCard`/`NButton` 等都会在自己的根节点写 `--n-color`，任何用 `var(--n-color)` 的自定义样式
   （如本项目 `.glass-surface-enabled`）一旦落在这些组件的子树里就会被染色。
2. 用户描述「蒙上一层」与实际「整块实色」可能是两回事，先区分「叠层（透明度低）」与「元素自身背景色被改」。
